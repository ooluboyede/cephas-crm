## Design decision under review
Use a protected transaction registry as an alternative to the proposed HMAC capability in Gate 0.1.5/0.1.8. It avoids a mutable context carrier and custom SQL cryptography. A separately authenticated issuer connection inserts one binding per database epoch, postmaster start, backend PID, full transaction ID and runtime login. RLS verifies active membership revision and expiry using database-controlled state. A unique key prevents rebinding even after expiry. Runtime has no authority-table grants or issuer function execution. Separate issuer logins represent trusted synthetic broker identities, not real OIDC authentication. The broker must securely associate the requested tuple with its actual pinned runtime connection; this end-to-end broker binding is not implemented or proven. Any production use requires reviewed broker/authentication, lifecycle, cleanup, rotation and recovery design. No signed capability or HMAC claims are made.
Scope: ordinary runtime arbitrary SQL row isolation. Revoked access cannot retrieve new authorised results through a new statement, but materialised/held cursor results from prior authority may persist; full revocation/noninterference, timing, resource exhaustion, all catalog channels, privileged compromise and full restore/failover are not proven. Same-login query text is a specific leakage risk; proof restricts pg_stat_activity and known direct query-text access functions. Independent reviewer must inventory other channels and consider distinct per-scope roles if shared-role isolation is insufficient. READ COMMITTED only. Registry expiry is statement-based, 30 seconds for proof. No claim of hard interruption of in-flight operations. Protected external monotonic state and registry retention remain open; do not garbage-collect active bindings.
## Reproduce
Run from repository root with Python 3 and Docker: python3 proof/tenant_boundary/run.py. Image defaults to postgres:18 and resolves to immutable digest before execution; set PROOF_POSTGRES_IMAGE to the exact recorded digest for reproduction. Exact image digest must be captured from successful evidence and pinned for later approval; tag selection is not a locked release. The harness generates ephemeral credentials, runs a network-none container, connects via TCP loopback using ordinary and privileged roles separately, and removes container in finally. No external dependencies beyond Python standard library, Docker and image. CI logs record digest, database version, SHA and test outcomes. No test skip allowed. GitHub job tests the PR merge tree; record head and merge SHA. Do not run bootstrap against an existing database.
