## Licence proof
Restricted canonical JSON encoding (ASCII schema, safe integers, sorted keys, no duplicates/floats, canonical whole envelope); Ed25519 verification delegates to OpenSSL; separate licence and trust-bundle domains. Bundle schema: schema_version, product, sequence, not_before, expires_at, sorted keys (kid, public_key, not_before, expires_at), sorted revoked IDs. Verify root signature, bundle lifetime, sequence floor and same-sequence digest when supplied. Verify licence signature, scope, module, time window and limits schema. Reject clock rollback against supplied trusted time. Public keys only in verifier; test harness generates ephemeral keys, deletes them on cleanup. No CEPHAS private key or real customer licence. This is a restricted JCS subset, not a general RFC 8785 implementation. Edition/module registry is synthetic; production keys and identifiers require compatibility with the existing CEPHAS issuer. No new company signing root is authorised.

## Audit proof
Canonical event digest chained by sequence and predecessor; signed checkpoint binds product, tenant/BU scope, sequence and digest with distinct domain. Checkpoint comes from assumed trusted independent custody. Reject rewrite, reorder, truncation, wrong scope/key and wrong expected checkpoint. Prototype verifies an exact fully checkpointed prefix, not unanchored tails. No production DB audit insertion, atomic outbox, external WORM service, checkpoint signing custody, crash reconciliation or retention policy implemented. No claim of privileged tamper detection if independent checkpoint and floor can also be rolled back.

## Remaining acceptance blockers
Production verifier must integrate actual approved issuer public keys and shared licence schema; independently generated fixed application golden vectors, recovery/rebind schema, rotation ceremonies, trusted durable floor/time, mandatory atomic floor persistence before enabling features, quota reservation/enforcement and module binding are not implemented. The API is a verifier returning candidate floor/digest, not an entitlement gate. Same-sequence digest enforcement depends on caller supplying trusted digest; production must require it for established floors. OpenSSL version logged but package/provider not pinned. Runtime checks use caller-injected trusted clock/binding/floor for test only; not a durable authority. Audit needs separate customer-controlled anchor, exact event schema with actor/correlation and atomic mutation/audit policy; this proof schema is deliberately reduced. Original recovery journal is not WORM. Full restore, identity integration, strict isolation profile, exact dependency compatibility and repo protection remain open. Do not claim Gate 0.1 closed or Gate 0.2 authorised. Independent reviewer should receive exact evidence and unresolved findings.
