## Company issuer compatibility blocker
Existing company policy is universal offline licensing, central private signing custody and public-only validators. Prior project records describe issuer v1 signing UTF-8 JSON.stringify(payload) in original property order, schemaVersion 1.0 and customer/product/tier/deployment/term/grace/limits/modules/features/key-version claims. CRM experiment instead uses sorted canonical JSON, schema_version 1, CRM-specific domain prefix and trust bundle. These are materially different candidate contracts. Prior records are not authoritative live issuer evidence. No matching issuer repository was visible in available GitHub inventory; do not infer exact product code, field types, encoding, signature envelope, key ID or public fingerprint from another product. Do not use Floot for CRM builds. Do not change issuer or generate company keys. Do not accept both formats via fallback. Before interoperability acceptance obtain approved public-only schema/version, exact serialization and envelope specification, registered CRM product ID, authenticated public key export and fingerprint definition, signed nonproduction fixture and independently verified rejection vectors. Verify real issuer public/private correspondence via issuer-side signed challenge, without retrieving private keys. Reconcile issuer grace policy and CRM proposed no silent grace explicitly. Do not expose production secrets or customer data. New CRM-specific proof is not a compatible licence adapter; production deployment remains blocked.

## State proof
Operator explicitly initializes separate SQLite state with verified bundle floor/digest and time. Reservation revalidates licence against persisted floor/digest/time under BEGIN IMMEDIATE, persists new floor/time and one daily transaction reservation atomically, rejects zero/exhausted quota, and distinguishes identical same-day/module duplicate request from conflicting reuse. Scope derived from trusted binding. No production CRM write, request-body digest, actual seat/record enforcement, lease or cross-store atomicity. Quota is per synthetic installation scope, not a final commercial definition. Failed reservations do not advance floor; deployment must separately persist newly accepted trust state and revocations even when feature action denied. State is single installation prototype; mandatory binding to deployment identity at store initialization and per-tenant floors must be reviewed before production.

Checkpoint verification requires exact signature and full event prefix. Store retains per-scope sequence and digest; reject lower sequence and divergent historical prefix even if a new checkpoint is signed. It is a local prototype, not independent WORM or a production signing/append service. SQLite file restore or privileged modification remains outside proof; independently protected authority, operator custody, crash/power-loss, whole-system rollback, atomic audit/outbox and retention remain open. No production keys. Six tests added for quota/idempotency, concurrency, persistent trust/time floors, missing state and equivocation, zero quota, and checkpoint fork/rollback/extension.
