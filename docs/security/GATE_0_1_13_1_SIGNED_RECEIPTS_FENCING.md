## Receipt contract
Disposable Ed25519 signer creates ephemeral key outside both database containers; public SPKI pinned in coordinator at explicit setup. Signature domain CEPHAS-CRM-RECOVERY-AUDIT-RECEIPT-V1 followed by NUL; canonical ASCII sorted JSON restricted to closed safe-integer schema (version, deployment, revision, previous, sequence, epoch, phase, audit_sequence, digest). Receipt digest hashes domain + payload + fixed-length signature. Verify exact encoding, signature, deployment and contiguous transition chain, unique epochs, permitted transitions and match external head before operations. Receipt appended atomically with head change in authority DB transaction; genesis explicit bootstrap only. Live coordinator floor pins observed revision/digest; valid older prefix rejected during same coordinator lifetime. Full receipt history bounded to 4096; overflow denies (not a production pagination/retention design). No external independent signer service, key rotation, persistent protected floor across coordinator restart, WORM retention or independently administered key custody. Same CI operator can access both clusters and key. Signed receipts alone do not prevent rollback of authority and coordinator floor together.

## Fencing and atomicity
Guard, mutation, quarantine, reconciliation and activation acquire the same authority head row lock (bounded lock wait). Cooperative callers serialize; activation requires exact expected epoch and matched primary/local/audit state. Primary mutation and outbox atomic; primary and authority commits remain separate. Mismatch denies subsequent operations; no blind tail adoption. Check anchored prefix digest as well as new local chain after primary commit. Read release is not atomic with network delivery or post-commit quarantine. No all-path fencing of legacy proof or actual application; no protection from admin bypass. Concurrent test uses separate connections and permits either pre-fence commit or denial after fence, no post-fence mutation. No production claim of fencing leases, signed two-person activation, trusted time or crash/failover guarantees.
