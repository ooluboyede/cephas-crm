## Internal remediation
The original self-bind inserted a row within the same transaction. Rolling back a savepoint could remove it and allow a new expiry. Bound the deadline to top-level transaction_timestamp +30 seconds, reject late initial or repeated binding after deadline. Savepoint rollback may still recreate a binding within the same fixed actor/scope and original deadline; no claim of immutable one-time issuance across savepoint rollback. Broker now pins authenticated session_user, backend PID and full xid8 and verifies that identity around its protected read; changed transaction/connection denies result even under same login. Fixed operation names, no caller SQL, actor or target tuple. Four additional tests cover independent same-login sessions, concurrent actors, same-role transaction replacement and restricted authority/legacy functions. Existing real 31-second expiry test now also covers actor binding expiry, savepoint rollback/rebind denial, late initial denial and fresh transaction success without another sleep.

## Proposed production trust protocol (requires D11-02/D11-03 approval)
1. Customer IdP authenticates actor; server verifies exact issuer, signature, audience, nonce/state, expiry and required MFA. Local immutable issuer+subject principal ID; active tenant/BU membership and action permission queried from authority. Browser/API cannot assert principal, SQL, role, connection identifiers or recovery epoch. Service identities distinct, no role fallback.
2. Separate trusted broker service owns credential access; only isolated broker network identity may connect to actor-role database endpoint. CRM API receives typed operations, never SQL handles, role passwords or raw driver sessions. Credential service provisions unique deployment/principal/tenant/BU login with SCRAM or qualified short-lived credential, no shared login; membership and role map changes by separate audited authority, not broker runtime. TLS verify-full, pinned database identity; no superuser, BYPASSRLS, owner, role creation or role inheritance. Credential rotation, retirement and orphan cleanup require qualification; size role counts and connection budgets per deployment. No production provisioning implementation exists yet.
3. Broker resolves fixed action to authorized scope and exact typed handler; opens one new authenticated physical connection, READ COMMITTED, captures session_user/PID/full xid8 and checks expected identity. Self-bind derives actor from session_user, protected actor map and live revision; no external issuer target selection. Bind expires at top-level transaction start +30s. Check recovery authority and membership before operation; RLS checks exact login, actor, scope, transaction, epoch, membership revision and deadline at statement start. Deny unrecognized operations, errors, unsupported isolation, missing state, replaced transaction and credentials. No client-accessible direct DB path; no pooling until independently qualified. Buffer bounded reads, recheck context and external recovery, commit, close; no data on failed checks or cleanup. Do not claim revocation retracts already released data.
4. Mutation profile is NOT implemented. Require fixed parameterized typed handlers, atomic audit/outbox, idempotency bound to actor+scope+action+canonical request digest, explicit membership-revocation serialization and rollback policy. Design approval and proof of revocation linearization, transaction deadline, commit outcome and concurrent authority changes before enabling writes. Read-only proof cannot certify arbitrary same-scope actions, mutations or OIDC integration.
5. Recovery requires independent protected authority and fenced ingress, broker and DB paths (R2). Existing recovery reader cannot prevent privileged coordinated rollback; no atomic cross-service cutover. No production recovery or licence state claims.

## Isolation profiles and trust assumptions
Shared profile: database-enforced row isolation against arbitrary SQL using ordinary actor-role credentials for foreign tenant/BU rows; no claim of preventing same-scope reads permitted by that role, resource abuse, timing, metadata/locks or all covert channels. Actor-role credentials are trusted broker-held; attacker with a stolen actor credential can act as that actor in its own allowed scope. A compromised broker, IdP, credential service, authority operator, DB superuser or host is outside this narrow claim. Separate database/cluster plus independently administered credentials, network and resource controls required for strict customer isolation profile; separate cluster alone does not prove noninterference. Explicit customer/owner threat-profile approval, role cardinality benchmark and deployment hardening required. Legacy target issuer remains regression-only in disposable harness; no deployment grant. No independent reviewer acceptance or named owner approval inferred.

## Remaining F-01 evidence
Real OIDC and actor mapping, actual isolated service/credential custody, provision/revoke and concurrent authority tests, mutation/atomic outbox boundary, externally protected recovery and threat-profile approval. Same-role transaction pinning is a safeguard against accidental connection/transaction replacement, not against a malicious trusted driver fabricating responses.
